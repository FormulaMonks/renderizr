# How Structurizr merges `workspace.dsl` with a saved `workspace.json`

Structurizr keeps every layout field of a view in `workspace.json`: element `x` and `y`, relationship `vertices`, `routing`, `position` and `jump`, and view `paperSize` and `dimensions`. The DSL has no syntax for any of them, so they live in `workspace.json` or come from a `!script` block. Structurizr Local and the `merge` command build the workspace from the DSL, then copy those fields from `workspace.json` with `DefaultLayoutMergeStrategy`. The strategy matches views by key, elements by canonical name, then name, then description, then id, and relationships by their two ends plus description, then id. Local writes the whole workspace back through one Jackson writer every time it parses the DSL and every time the author saves.

For edit mode this means:

- **Bring the DSL in with `merge`.** One `merge -workspace workspace.dsl -layout workspace.json -output <temporary file>` parses the DSL and applies Structurizr's own matching in a single JVM run of about 1.3 seconds, so edit mode needs no port of the merge strategy and lays out a workspace exactly as Local does.
- **Save the whole workspace, as Local does.** Builds read the model from `workspace.json`, so a file that only gained layout would keep the model from the last time something wrote it.
- **Match Structurizr's bytes.** Keeping the key order of Structurizr's own file and printing it with Jackson's pretty-print rules reproduces Structurizr's output byte for byte. Local's save stamps (`id`, `lastModifiedDate`, `lastModifiedAgent`, `lastModifiedUser`) still change on every save.
- **Expect the 2026 DSL rules.** Structurizr 2026 refuses the acceptance fixture's DSL, because its `ContextInternal` filtered view sits on a view with automatic layout. It also changed the `autoLayout` defaults and dropped `implementation` and `applied` from `automaticLayout`.

## Export

`export -format json` writes the workspace exactly as the DSL builds it ([`AbstractCommand.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/command/AbstractCommand.java#L51-L116)). It runs no layout algorithm and ignores any `workspace.json` beside the DSL.

- **Views with a stored layout**: every element entry carries `x` and `y`, both `0` when nothing set them, because Jackson's non-empty filter keeps integer zeros. Coordinates and vertices come only from a `!script` block, and the export adds no `paperSize` or `dimensions`.
- **Views with `autoLayout`**: every element sits at `0, 0`, and the view carries an `automaticLayout` object. structurizr-java 5.0.2 writes `applied: false, edgeSeparation: 0, implementation: "Graphviz", nodeSeparation: 300, rankDirection: "TopBottom", rankSeparation: 300, vertices: false` for a bare `autoLayout` (observed; [`AutoLayoutParser.java` 5.0.2](https://github.com/structurizr/java/blob/v5.0.2/structurizr-dsl/src/main/java/com/structurizr/dsl/AutoLayoutParser.java#L28-L66), [`ModelView.java` 5.0.2](https://github.com/structurizr/java/blob/v5.0.2/structurizr-core/src/main/java/com/structurizr/view/ModelView.java#L169-L171)). The 2026 library dropped `implementation` and `applied` and changed the defaults ([`AutomaticLayout.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/AutomaticLayout.java#L6-L18), [`AutoLayoutParser.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-dsl/src/main/java/com/structurizr/dsl/AutoLayoutParser.java#L27-L95), [library changelog 6.0.0](https://github.com/structurizr/structurizr/blob/v2026.09.19/changelog-library.md#L70-L83)): a bare `autoLayout` writes `edgeSeparation: 50, nodeSeparation: 50, rankDirection: "LeftRight", rankSeparation: 100, vertices: true`, and the statement takes `[rankDirection] [rankSeparation] [nodeSeparation] [edgeSeparation] [vertices]`. The [DSL reference](https://docs.structurizr.com/dsl/language#autolayout) still documents top to bottom and 300.
- **`applied`**: nothing in structurizr-java 5.0.2 sets it to `true`. Even `export -format static` in structurizr-cli 2025.11.09, which runs Graphviz and fills coordinates, `dimensions` and `paperSize` for automatic-layout views, leaves `applied: false` (observed; [`ExportCommand.java` 2025.11.09](https://github.com/structurizr/cli/blob/v2025.11.09/src/main/java/com/structurizr/cli/export/ExportCommand.java#L138-L153)). The 2026 library has no such field, and its JSON reader drops it with every other key it does not know.
- **Graphviz**: the 2026 distribution never needs it. No module of the application depends on `structurizr-autolayout`, and Structurizr's browser UI lays out automatic-layout views with Dagre when it draws them. With structurizr-cli 2025.11.09, `export -format json` succeeds with no `dot` on the PATH, and only `export -format static` fails, with `Cannot run program "dot"` (observed).
- **Other content**: the inspections add `structurizr.inspection.*` workspace properties. A DSL that reads no other file and runs no script keeps its own source, base64-encoded, in the `structurizr.dsl` workspace property ([`StructurizrDslParser.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-dsl/src/main/java/com/structurizr/dsl/StructurizrDslParser.java#L148-L158)). The 2026 `export` also adds default views when the DSL defines none.
- **2026 refuses the acceptance fixture.** Since structurizr-java 6.0.0 the DSL rejects a filtered view whose base view has automatic layout ([`FilteredViewParser.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-dsl/src/main/java/com/structurizr/dsl/FilteredViewParser.java#L76-L79)). `test/__fixtures__/acceptance/workspace.dsl` bases `ContextInternal` on `Context`, which has `autoLayout lr`, so parsing stops with `The view "Context" has automatic layout enabled - this is not supported for filtered views`. structurizr-cli 2025.11.09 accepts the file.

## Merge

### What it copies

`merge` and Local both call `ViewSet.copyLayoutInformationFrom` and then copy `lastSavedView` ([`MergeCommand.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/command/MergeCommand.java#L76-L80), [`LocalFileSystemWorkspaceAdapter.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/component/workspace/LocalFileSystemWorkspaceAdapter.java#L128-L136), [`Configuration.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/Configuration.java#L144-L146)). For each view it merges, `DefaultLayoutMergeStrategy` copies these fields ([`DefaultLayoutMergeStrategy.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/DefaultLayoutMergeStrategy.java#L36-L82), [`ElementView.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/ElementView.java#L96-L101), [`RelationshipView.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/RelationshipView.java#L272-L279)):

| Field | When the merge copies it | Seen in |
| --- | --- | --- |
| Element `x`, `y` | The element matches. The saved values replace the DSL's, `0, 0` included. | E1, E11 |
| Relationship `vertices` | The relationship and both its ends match. Saved vertices replace the DSL's, and a relationship saved without vertices loses the DSL's. | E1, value probe `no-vertices` |
| Relationship `routing`, `position`, `jump` | The relationship matches. A value missing from the save clears the DSL's. | E1, E10 |
| View `paperSize`, `dimensions` | The DSL view has none, which holds unless a `!script` set one. | E1 |
| `views.configuration.lastSavedView` | The merge covers every view: `merge` without `-view`, and Local. | E1, E1b |

The model, styles, themes, view titles and descriptions, dynamic-view order, animation steps and `automaticLayout` all come from the DSL. The JSON reader ignores keys it does not know ([`AbstractJsonReader.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-client/src/main/java/com/structurizr/io/json/AbstractJsonReader.java#L8-L15)), so a field Structurizr does not define disappears in a merge (E1). The reader also coerces layout values: it truncates fractional coordinates, vertices and dimensions to integers, keeps negative coordinates, clamps `position` to 0–100, drops an unknown routing mode or paper size, and refuses the whole file when `jump` is not a boolean (value probes).

The merge leaves three kinds of view alone ([`ViewSet.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/ViewSet.java#L1068-L1145)):

- a view with `autoLayout` in the DSL, whatever `workspace.json` holds for it (E1). Removing `autoLayout` from the DSL brings the saved coordinates back (E13);
- filtered views and image views, which have no layout of their own;
- a view whose `mergeFromRemote` flag is false, which only Java code or a `!script` can set (E12; [`ModelView.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/ModelView.java#L168-L185)).

### How it matches

- **Views** ([`ViewSet.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/ViewSet.java#L1147-L1167)): same key; else same type-derived name, such as "Container View: Shop", and same description. A view whose key changes keeps its layout while its description stays the same, and loses it when both change (E8).
- **Elements** ([`DefaultLayoutMergeStrategy.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/DefaultLayoutMergeStrategy.java#L91-L113)), searched among the elements of the saved view: same canonical name; else same name and type; else same non-empty description and type; else same id and type. The first match wins. An element with no match keeps what the DSL gave it, which leaves it unplaced at `0, 0` unless a `!script` placed it, and the log says "There is no layout information for the element named …".
- **Relationships** ([`DefaultLayoutMergeStrategy.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-core/src/main/java/com/structurizr/view/DefaultLayoutMergeStrategy.java#L115-L177)): both ends must have matched; then same source, destination and description; else same source, destination and id. In a dynamic view the relationship's description and order in that view must match too.

### Renames and moves

- **Renamed, description kept**: the description step matches it (E2).
- **Renamed and redescribed, in the same place in the DSL**: the id step matches it, because the DSL hands out ids in the order it meets elements (E3).
- **Renamed and redescribed after its id shifted**: nothing matches, so it falls back to the `!script` position, or to `0, 0` without a script (E4, E5). When the shifted id now belongs to another element of the same type in that view, the merge copies that element's position, and the log stays silent: adding one person at the top of the acceptance DSL and renaming "Card gateway" puts it on top of "Courier" (E4b).
- **Moved to another parent, or parent renamed**: the canonical name changes, and the name-and-type step matches it as long as no other element of that type shares the name in that view (E6 moves a container instance to another deployment node, E7 renames "Shop"). When two such elements share a name, both take the first one's position (read from the code).
- **Relationship described differently**: the id step matches it (E9).

The [Local troubleshooting page](https://docs.structurizr.com/local/troubleshooting) describes the same failure cases and recommends explicit view keys.

## Structurizr Local

This section comes from reading the code at `v2026.09.19`; no Structurizr Local ran for this research.

### Loading a folder

Local reads its data folder through [`LocalFileSystemWorkspaceAdapter`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/component/workspace/LocalFileSystemWorkspaceAdapter.java#L53-L147):

- **`workspace.dsl` present**: Local serves `workspace.json` untouched when it is newer than every other file in the folder. Otherwise it parses the DSL with every DSL feature on (`!script`, plugins, `!include`, `!docs`, `!adrs`), validates the scope, runs the inspections, adds default views when the DSL has none, merges the layout from `workspace.json` as above, sets `id` to the workspace number (1 in single-workspace mode) and `lastModifiedDate` to the clock, and writes the result to `workspace.json` straight away, before the author edits anything.
- **Only `workspace.json`**: Local serves it, and writes a `workspace.dsl` from its `structurizr.dsl` property when the file carries one.
- **Neither file**: single-workspace mode writes a template `workspace.dsl` ([`LocalFileSystemSingleWorkspaceAdapter.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/component/workspace/LocalFileSystemSingleWorkspaceAdapter.java#L24-L32)).
- The browser receives the merged workspace as compact JSON from `GET /api/workspace/1` ([`LocalWorkspaceApiController.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/web/api/LocalWorkspaceApiController.java#L23-L36)).

### Saving

The diagram editor saves the whole workspace. Every 5 seconds while changes are unsaved, it sets `lastSavedView` to the view on screen and sends the workspace it holds, every view included, in a `PUT /api/workspace/1` ([`diagrams.jsp`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/webapp/WEB-INF/jsp/diagrams.jsp#L1264-L1274), [`load-via-api.jspf`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/webapp/WEB-INF/fragments/workspace/load-via-api.jspf#L41-L58), [`structurizr-client.js`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/resources/static/static/js/structurizr-client.js#L73-L99), [`auto-save.jspf`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/webapp/WEB-INF/fragments/workspace/auto-save.jspf)). The server then ([`WorkspaceComponentImpl.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/component/workspace/WorkspaceComponentImpl.java#L308-L393), [`LocalFileSystemWorkspaceAdapter.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/component/workspace/LocalFileSystemWorkspaceAdapter.java#L159-L175)):

1. refuses a body larger than `structurizr.workspace.maxsize`;
2. parses it into a workspace, which drops unknown keys and coerces values as the merge does, and validates its scope;
3. sets `id` to the workspace number and `lastModifiedDate` to the server's clock, to the second, written as `yyyy-MM-ddTHH:mm:ssZ` in UTC;
4. removes the users and visibility from `configuration` and keeps its `scope`;
5. serializes it with the writer `export` and `merge` use, overwrites `workspace.json`, and indexes it for search.

The page sets `lastModifiedAgent` to `structurizr/diagrams/<random id>` and `lastModifiedUser` to its anonymous user name, a number derived from a hash code, and both reach the file ([`AbstractWorkspaceController.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/web/workspace/authenticated/AbstractWorkspaceController.java#L91), [`AbstractController.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/web/AbstractController.java#L72-L74), [`AnonymousAuthenticationExtractor.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/web/security/AnonymousAuthenticationExtractor.java#L12-L14)). The code also shows the page writing back what drawing put into the views it holds: `dimensions` of 2000 by 2000 for any drawn view that had none, the coordinates Dagre gave the elements of automatic-layout views it drew, and a Dagre layout, saved by the next autosave, for an editable stored-layout view whose elements all sat at `0, 0` ([`structurizr-diagram.js`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/resources/static/static/js/structurizr-diagram.js#L542-L551) lines 542–551, 627–660, 989–1006 and 4188–4200).

**Format** ([`AbstractJsonWriter.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-client/src/main/java/com/structurizr/io/json/AbstractJsonWriter.java#L16-L33), [`WorkspaceUtils.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-client/src/main/java/com/structurizr/util/WorkspaceUtils.java#L22-L50)): Jackson sorts object properties alphabetically and leaves out `null` and empty values. It indents by two spaces, writes `"key" : value`, keeps arrays inline (`[ {` … `}, {` … `} ]`), writes `{ }` and `[ ]` for empty containers, ends without a final newline, and uses the JVM's line separator, which is LF on macOS and Linux and, by Jackson's default indenter, CRLF on Windows. Arrays follow each model class's own sort order, and maps such as `properties` keep Java's `HashMap` order. `export` and `merge` write UTF-8; Local's save uses the JVM's default charset, which is UTF-8 since Java 18. Two exports of one DSL come out byte-identical (observed), and [`jackson_format.py`](structurizr-layout-merge/jackson_format.py) rebuilds five files Structurizr wrote, byte for byte, from a key-order-preserving parse.

**Other files** ([`Configuration.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/configuration/Configuration.java#L29-L30), [`ApacheLuceneSearchAdapter.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/component/search/ApacheLuceneSearchAdapter.java#L52-L58), [`diagrams.jsp`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/webapp/WEB-INF/jsp/diagrams.jsp#L539-L567), [`LocalFileSystemWorkspaceAdapter.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/component/workspace/LocalFileSystemWorkspaceAdapter.java#L263-L289)): the work folder `.structurizr/` inside the data folder holds `logs/structurizr.log`, the search index `index/`, which Local rebuilds at start-up, and the thumbnails `1/images/<view key>-thumbnail.png` and `<view key>-thumbnail-dark.png`, plus `thumbnail.png` for the first view. The editor uploads a thumbnail after each save and each change of view. Other uploaded images go to `images/` in the data folder.

### Watching the DSL and its includes

Local polls the data folder once a second ([`LocalFileSystemWorkspaceAdapter.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/component/workspace/LocalFileSystemWorkspaceAdapter.java#L40-L48), [lines 206–228](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/component/workspace/LocalFileSystemWorkspaceAdapter.java#L206-L228)). A timer records the newest modification time of any file under it, and skips every name that starts with a dot (such as `.structurizr` and `.git`), `structurizr.properties`, and `workspace.json` when `workspace.dsl` sits beside it. Each load of the workspace compares that time with `workspace.json`, so a change to the DSL, or to any file it includes from inside the data folder, makes the next page load parse and merge again. A file included from outside the data folder, or by URL, never triggers a parse. An open page reloads by itself only when `structurizr.autoRefreshInterval` is above zero: it then polls `/workspace/lastModified` and reloads once that time grows and nothing is unsaved ([`auto-refresh.jspf`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/webapp/WEB-INF/fragments/workspace/auto-refresh.jspf), [`WorkspaceLastModifiedController.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-application/src/main/java/com/structurizr/server/web/workspace/authenticated/WorkspaceLastModifiedController.java#L23-L27)).

This ordering can hide a DSL change: the author edits the DSL while a page holds unsaved layout changes, the next autosave writes the model the page loaded before the edit, with a modification time later than the DSL's, and Local serves that file until another file in the folder changes.

## Layout in a `!script` block

The `!script groovy` block of the acceptance DSL sets `x`, `y` and vertices while the DSL parses, before any merge, and `export`, `merge` and Local all run scripts by default ([`StructurizrDslParser.java`](https://github.com/structurizr/structurizr/blob/v2026.09.19/structurizr-dsl/src/main/java/com/structurizr/dsl/StructurizrDslParser.java#L74-L92)). The merge treats the script's values like anything else the DSL produced:

- For an element that `workspace.json` holds in that view, the saved `x` and `y` win, `0, 0` included (E10, E11). Changing a coordinate in the script has no effect once the element is in `workspace.json`.
- For a relationship that `workspace.json` holds, the saved `vertices`, `routing`, `position` and `jump` win, and a value missing from the save clears what the script set (E10, value probe `no-vertices`).
- An element or relationship that `workspace.json` lacks keeps the script's values: one the DSL gained after the last save (E10), one the merge fails to match (E4), and a relationship with an unmatched end (E1).
- A script can call `setMergeFromRemote(false)` on a view, which then keeps the script's layout on every merge. The flag never reaches the JSON (E12).
- Views with `autoLayout` ignore both the script's layout and the saved one.

Once `workspace.json` holds a view, the script's coordinates only seed the elements the saved layout lacks. `pnpm fixtures:acceptance` exports into a temporary folder and overwrites `workspace.json` with the result, so the fixture carries the script's layout, and a layout saved into that file would not survive the next regeneration.

## What this means for edit mode

- **DSL in**: run `merge -workspace workspace.dsl -layout workspace.json -output <temporary file>`, or `export -workspace workspace.dsl -format json -output <temporary folder>` while no `workspace.json` exists, and always pass `-output`. That costs one cold JVM per DSL change, about 1.3 seconds on the acceptance DSL, and returns what Local would write apart from `id` and `lastModifiedDate`. A TypeScript port of the strategy pays off only for a merge with no JVM at hand, or for matching better than Structurizr does, for example by the `structurizr.dsl.identifier` property that every DSL element with an identifier carries. Either choice would make edit mode and Local lay out the same files differently.
- **Save**: write the whole workspace, starting from the last `merge` output and applying the author's layout by element and relationship id, which stay stable within one DSL run. Write only fields Structurizr defines, as integers, with `position` within 0–100 and `jump` as a boolean, because Structurizr drops or refuses anything else.
- **Format**: keep the key order of the file Structurizr wrote, put any key edit mode adds in alphabetical order, leave out `null` and empty values, and print with Jackson's rules and the line ending the file already uses. The output then matches Structurizr's bytes, and a save that moves one element changes only its `x` and `y` lines. Matching a Local save byte for byte stays out of reach, because Local stamps `id`, `lastModifiedDate`, `lastModifiedAgent` and `lastModifiedUser` on every save. `JSON.parse` also moves integer-like map keys to the front, which only matters for a `properties` map with such keys.
- **Live reload**: decide whether the DSL changed by comparing its folder with the last DSL run, and never let a save from a page that loaded an earlier DSL run replace the model of a later one. Local's ordering gets both wrong.
- **Automatic-layout views**: trust `automaticLayout` even when a Local save left coordinates in the view.
- **Java**: ask for Java 21, 23 or 25, or the `-noble` image; Java 26 breaks some Groovy scripts.
- **Acceptance fixture**: Structurizr 2026 needs `ContextInternal` to filter a view with a stored layout, and the fixture's `!script` and a saved `workspace.json` compete for the same layout.

## Reproduce

The scripts need Python 3, a Structurizr CLI (`STRUCTURIZR_CLI`, or `structurizr-cli` on the PATH) and Java 21; set `JAVA_HOME` to pick the JVM. Each one writes only under the scratch folder it receives.

```bash
cd docs/research/structurizr-layout-merge
scratch="$(mktemp -d)"
python3 merge_experiments.py ../../../test/__fixtures__/acceptance/workspace.dsl "$scratch"
python3 value_experiments.py "$scratch"
python3 jackson_format.py "$scratch/e0-base/export/workspace.json" "$scratch/e1-merged.json"
bash time-export.sh ../../../test/__fixtures__/acceptance/workspace.dsl 5
```
