# React Flow against the Structurizr feature inventory

Resolves [#24](https://github.com/FormulaMonks/renderizr/issues/24), part of the renderer replacement mapped in [#21](https://github.com/FormulaMonks/renderizr/issues/21). Audited against `@xyflow/react` 12.12.0 (`@xyflow/system` 0.0.83) and the vendored renderer in `vendor/structurizr/js/structurizr-diagram.js` (8,171 lines) as of commit `3c98222`.

## Verdict in one paragraph

React Flow is a viewport, a node/edge store and a measurement loop; it is not a diagram renderer. Of the twenty-odd things the vendored renderer does for read-only rendering, React Flow gives four out of the box (pan/zoom/fit, parent-relative positioning, arrow markers, dark-mode canvas), needs a custom node or edge component for about a dozen (every shape, every boundary, every edge path, every label), and does not do five at all (size a parent to its children, route through stored vertices, place a label at a percentage of a path, draw jump-overs, run animations). None of the "not supported" items is a blocker: each is a few dozen lines of geometry we own, and in every case the vendored renderer is doing the same arithmetic itself today rather than getting it from JointJS. The real trade is that React Flow removes 706 KB minified / 201 KB gzipped (JointJS, jQuery, the five vendor files) and adds 420 KB / 131 KB (React, ReactDOM, React Flow and its CSS), a net saving of roughly 285 KB / 71 KB, about a quarter of today's single-file artifact. It has no network dependency and works from `file://`.

## How to read the table

"Out of the box" means a prop or exported helper does it with no code of ours beyond wiring. "Custom node/edge" means React Flow supplies the slot (`nodeTypes`, `edgeTypes`, `BaseEdge`, `EdgeLabelRenderer`) and we supply the drawing. "Not supported" means React Flow has no concept of it and we compute it entirely ourselves, with React Flow only hosting the result. The last column names where the vendored renderer does it today, so the ticket that implements the item knows which code to read.

## Can a parent node be sized to its children automatically?

No. React Flow's sub-flow model positions children relative to a parent and moves them with it, but the parent's size is whatever its own content or `style` says; the docs show parents given "a fixed width and height … by passing the style option" and warn that parents must appear before children in the array. The only built-in growth is `expandParent: true` on a child, which enlarges the parent when a child is dragged past its border, and the maintainers note "there is no 'auto-collapse' option to reverse the resize"; it is a drag-time behaviour and does nothing for a static layout. The pattern, and what the renderer's `reposition` does today, is a bottom-up pass over the nesting tree before the nodes reach React Flow: for each parent, take the union of its children's boxes (we know every leaf's size from the element style, so no measurement round-trip is needed), add Structurizr's padding (`clusterPadding` 50 on each side, plus 15 margin and the name/metadata line heights at the bottom), enforce the minimum width of icon + name, and emit the parent with that `style.width/height` and a `position` equal to the padded minimum corner; then convert every child's stored absolute `x,y` to parent-relative by subtracting that corner. `getNodesBounds(children)` can do the union once nodes are measured, but doing it from model units before the first render avoids a flash of unsized boundaries. Because the leaf dimensions are fixed by style, this pass is pure and deterministic, which is exactly what a static artifact wants.

## Can a label be placed at an arbitrary percentage along a custom path?

Not with React Flow's helpers; yes with ours. `getBezierPath`, `getSmoothStepPath` and `getStraightPath` return `[path, labelX, labelY, offsetX, offsetY]` where the label point is the path midpoint (or `stepPosition` for smooth-step), and none of them accepts waypoints. Structurizr's `position` is a 0–100 fraction of the whole connection length including vertices, with two labels stacked vertically at that point. Since the custom edge already owns the path, it also owns the geometry: for a polyline, walk the segments until the cumulative length reaches `position / 100 × total`; for Bézier segments, sample at fixed `t` steps or read `getTotalLength()`/`getPointAtLength()` from a `ref` to the rendered `<path>` in a layout effect (one extra render). `EdgeLabelRenderer` then portals an HTML `div` above the SVG at that point; it has `pointer-events: none` by default, which is what a read-only label wants, and the description/technology stack becomes two lines of flexbox instead of two labels with hand-computed y-offsets.

## How dashed strokes and marker ends are done

Dashes are SVG: the edge forwards `style={{ stroke, strokeWidth, strokeDasharray }}` to `BaseEdge`, and the values are the renderer's own (`4t 4t` for Dashed, `t 2t` for Dotted, where `t` is thickness). Element borders use the same `stroke-dasharray` on the shape's inline SVG. Markers are a React Flow feature: an `EdgeMarker` `{ type: MarkerType.ArrowClosed, color, width, height, strokeWidth, orient, markerUnits }` on `markerEnd` (per edge, or once via `defaultEdgeOptions`) makes React Flow render a deduplicated `<defs>` of `<marker>` elements with ids derived from the properties and reference them as `url(#id)` on the path. Scaling the head with thickness as `calculateArrowHead` does (`10 × thickness`, capped at 50) is just `width`/`height` on the marker. A bespoke head shape, if #28 wants one, is also possible: `BaseEdge` accepts any `url(#id)` string, so we can render our own `<defs>` once.

## Offline and `file://` operation

React Flow has no network dependency. The production bundle contains zero `fetch(`, `XMLHttpRequest` or `new Image(` calls and no dynamic `import()`, so Vite's single-file inlining keeps working with one script tag. The only URLs in the bundle are SVG/XHTML namespaces and two `https://reactflow.dev` strings used by the attribution link and an error message. The stylesheet (`base.css` 13.6 KB, or `style.css` 18.6 KB) has no `@import` or `url()` and is inlined like any other CSS. Browser APIs used are `ResizeObserver` (guarded with `typeof` checks), `matchMedia('(prefers-color-scheme: dark)')` for `colorMode="system"`, and d3-zoom's pointer events; all are available from `file://`. The one thing React Flow needs that a 0×0 container cannot give is a measured size, the same constraint `whenMeasurable` in `src/pages/diagrams.ts` already works around for the Claude-artifact host, so that guard carries over unchanged. Attribution: the library is MIT and the docs say anyone is free to remove the corner attribution with `proOptions={{ hideAttribution: true }}`, while asking users who do to consider a Pro subscription; this is a policy choice for #26 to record, not a licensing constraint.

## What the later tickets should know

Edge semantics ([#29](https://github.com/FormulaMonks/renderizr/issues/29)): the vendored renderer connects edges centre-to-centre and clips at the bounding box (`defaultConnectionPoint: { name: 'bbox' }`), not at fixed handles. React Flow's default edges run between `Handle`s at Top/Bottom/Left/Right, which would visibly change every diagram. The free "Floating Edges" example shows the fix: read both nodes with `useInternalNode`, intersect the centre line with each node's rectangle (`internals.positionAbsolute` plus `measured`), and feed those points to the path; for non-rectangular shapes (Person, Cylinder, Hexagon) the bbox intersection is what Structurizr does anyway. With stored vertices, the first and last segments should aim at the first/last vertex, not at the other node's centre. `adjustVertices` is disabled upstream, so parallel vertex-less relationships overlap today; React Flow will not fix that either, and it is a candidate improvement rather than a parity requirement.

Boundaries ([#30](https://github.com/FormulaMonks/renderizr/issues/30)): compute sizes bottom-up from model units before rendering (section above); emit parents before children; use `zIndexMode="auto"` so nested children and their edges sit above the boundary fill; groups nest via the `structurizr.groupSeparator` property and get their own `Group:<name>` styles; the legacy enterprise boundary and the deployment-node pruning loop are both behaviours to carry over. Boundary opacity is `0.6` in edit mode and `1.0` read-only, so we only ever need the opaque case.

Visual language ([#28](https://github.com/FormulaMonks/renderizr/issues/28)): the renderer's text layout is canvas-measured (`calculateWidth` via `measureText`, `breakText` via JointJS) and fixed-height; HTML text in custom nodes gives wrapping and ellipsis for free, so the question becomes what to do when content overflows the model-unit box, which the renderer today only logs. Icon position (`Top`/`Bottom`/`Left`), the 1.4× name and 0.7× metadata font ratios, the colour-shading by opacity (`shadeColor(color, 100 − opacity)`) and the dark-mode defaults (`#111111` canvas, `#cccccc` text) are the constants to preserve or deliberately change.

Artifact constraints ([#26](https://github.com/FormulaMonks/renderizr/issues/26)): React Flow needs the container to have a non-zero size before the first `fitView`, the same condition `whenMeasurable` guards; keep that guard and call `fitView` from `useNodesInitialized` rather than `onInit`. `nodeTypes`/`edgeTypes` must be module-level constants or React Flow warns and re-mounts every node. The Vite config needs JSX enabled (`esbuild: { jsx: 'automatic' }`; `@vitejs/plugin-react` only for HMR). React 19 is fine (`peerDependencies: react >= 17`). Decide whether to hide the attribution.
