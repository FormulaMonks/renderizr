# How Structurizr renders diagrams, math and GitHub-flavored syntax in documentation

Research notes on how Structurizr turns the Markdown and AsciiDoc of documentation sections and decisions into a page, so that Renderizr can decide which of GitHub's advanced formatting features to support on its documentation and decisions pages.

## 1. Markdown and AsciiDoc libraries and their extensions

Structurizr renders documentation in the browser. The DSL only reads each file into a section's `content` as written ([`DefaultDocumentationImporter.java` L91–L93](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-import/src/main/java/com/structurizr/importer/documentation/DefaultDocumentationImporter.java#L91-L93)), and the page converts it with [markdown-it](https://markdown-it.github.io/) or [asciidoctor.js](https://github.com/asciidoctor/asciidoctor.js) ([docs: Documentation](https://docs.structurizr.com/server/documentation), [source](https://github.com/structurizr/structurizr.github.io/blob/530a96451b93f8fb96337b58aaaa1ec8c0ad4589/commands/03-server/23-documentation/index.md?plain=1#L13-L19)). One file, `structurizr-content.js`, holds the whole conversion for both the documentation page and the decisions page ([`documentation.jsp` L4–L10](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/documentation.jsp#L4-L10), [`decisions.jsp` L5–L11](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/decisions.jsp#L5-L11)).

### Markdown options

Structurizr creates markdown-it with one option, `html: !safeMode`, and adds the footnote plugin ([`structurizr-content.js` L10–L14](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L10-L14)). Everything else is markdown-it's default preset ([`default.mjs` L5–L36](https://github.com/markdown-it/markdown-it/blob/14.1.1/lib/presets/default.mjs#L5-L36)):

- **Tables**: on. The default preset enables the GFM table rule ([`parser_block.mjs` L25](https://github.com/markdown-it/markdown-it/blob/14.1.1/lib/parser_block.mjs#L25)).
- **Strikethrough** (`~~text~~`): on ([`parser_inline.mjs` L34](https://github.com/markdown-it/markdown-it/blob/14.1.1/lib/parser_inline.mjs#L34)).
- **Autolinks**: only CommonMark's `<https://…>` form ([`parser_inline.mjs` L38](https://github.com/markdown-it/markdown-it/blob/14.1.1/lib/parser_inline.mjs#L38)). Bare URLs stay text, since `linkify` is `false` ([`default.mjs` L18](https://github.com/markdown-it/markdown-it/blob/14.1.1/lib/presets/default.mjs#L18)).
- **Footnotes** (`[^1]`): on in the application through markdown-it-footnote ([L14](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L14)); off in the `ui` repo. Without the plugin, markdown-it reads `[^1]: text` as a link reference definition, so `[^1]` becomes a link to `text` (checked by rendering the sample with markdown-it 14).
- **Task lists** (`- [ ]`), **emoji shortcodes** (`:smile:`) and **alerts** (`> [!NOTE]`): off. No plugin for any of them loads, so `[ ]` and `:smile:` stay literal text and an alert stays an ordinary blockquote whose first line reads `[!NOTE]`.
- **Typographer** (smart quotes, `--` to a dash): off ([`default.mjs` L21](https://github.com/markdown-it/markdown-it/blob/14.1.1/lib/presets/default.mjs#L21)).
- **Raw HTML**: on whenever safe mode is off (see section 5).

Beyond the Markdown syntax, Structurizr overrides three markdown-it rules: images (to embed views and resolve workspace images, section 3), inline code (for math, section 4) and fences (for `katex` blocks, section 4) ([L16–L64](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L16-L64)).

### AsciiDoc options

Structurizr preprocesses AsciiDoc line by line (dropping passthroughs in safe mode, and turning `image::embed:…[]` and `image::…[]` lines into `pass:[…]` HTML of its own), then calls `new Asciidoctor().convert(preparsedContent)` with no options and no attributes ([L203–L232](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L203-L232)). So no `source-highlighter`, `stem`, `icons` or `experimental` attribute is set by Structurizr; an author can still set document attributes in the file itself. Asciidoctor's own tables, footnotes, checklists and admonitions work as asciidoctor.js renders them, styled by [`asciidoctor-2.2.6.css`](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/css/asciidoctor-2.2.6.css).

## 2. Fenced `mermaid`, `plantuml` and `kroki` blocks

**The page draws none of them.** The docs say so directly: "The Structurizr documentation renderer does not natively support diagramming formats such as PlantUML or Mermaid", and they ask authors to preprocess the source into image tags, with a DSL plugin as the recommended way ([docs: Images](https://docs.structurizr.com/server/documentation/images), [source L20–L29](https://github.com/structurizr/structurizr.github.io/blob/530a96451b93f8fb96337b58aaaa1ec8c0ad4589/commands/03-server/23-documentation/03-images.md?plain=1#L20-L29)). The fence rule only intercepts `katex` ([L46–L64](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L46-L64)). Without a plugin, a ` ```mermaid ` block reaches the page as a code block: markdown-it writes `<pre><code class="language-mermaid">`, and highlight.js, which has no `mermaid`, `plantuml` or `kroki` grammar, leaves it plain (section 5).

**Two opt-in DSL plugins rewrite the source at parse time.** `com.structurizr.dsl.plugin.documentation.Mermaid` and `com.structurizr.dsl.plugin.documentation.PlantUML` arrived in the application's 2026.02.01 release ([changelog L175–L176](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/changelog-application.md?plain=1#L175-L176)). They live in `structurizr-application`, outside the DSL library ([folder](https://github.com/structurizr/structurizr/tree/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation)), and the archived `structurizr-cli` and `structurizr/java` trees hold no such classes. The author turns one on with `!plugin com.structurizr.dsl.plugin.documentation.Mermaid` placed after every `!docs`, `!adrs` and `views` ([docs: Mermaid plugin](https://docs.structurizr.com/dsl/plugins/mermaid), [source L66–L92](https://github.com/structurizr/structurizr.github.io/blob/530a96451b93f8fb96337b58aaaa1ec8c0ad4589/dsl/plugins/mermaid.md?plain=1#L66-L92); [PlantUML plugin](https://docs.structurizr.com/dsl/plugins/plantuml)). The parser runs a plugin as soon as its `!plugin` line (or block) ends ([`StructurizrDslParser.java` L312–L321](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-dsl/src/main/java/com/structurizr/dsl/StructurizrDslParser.java#L312-L321), [`PluginDslContext.java` L26–L31](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-dsl/src/main/java/com/structurizr/dsl/PluginDslContext.java#L26-L31)), and restricted mode turns plugins off ([L136](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-dsl/src/main/java/com/structurizr/dsl/StructurizrDslParser.java#L136)).

What the Mermaid plugin does ([`Mermaid.java`](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/Mermaid.java)):

- It visits the workspace and every element that carries documentation, and rewrites the `content` of every section and every decision in place with `setContent` ([L26–L48](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/Mermaid.java#L26-L48)).
- It matches a Markdown block with `((^```mermaid\R)((^.*\R)+?)(^```))` in multiline mode, and an AsciiDoc block with `((^\[mermaid.*?]\R)(^\.\.\.\.\R)((^.*\R)+?)(^\.\.\.\.))` ([`AbstractDiagramsAsCodePlugin.java` L7–L13](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/AbstractDiagramsAsCodePlugin.java#L7-L13)). So the fence must be exactly three backticks and `mermaid` at the start of a line with nothing after the info string; `~~~`, four backticks, an indented fence or ` ```mermaid title` stay as written.
- It replaces each match with `![](<mermaid.url>/<format>/<encoded>)` in Markdown or `image::<mermaid.url>/<format>/<encoded>[]` in AsciiDoc ([L15–L16](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/AbstractDiagramsAsCodePlugin.java#L15-L16), [`Mermaid.java` L50–L88](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/Mermaid.java#L50-L88)).
- It encodes the source with the same `MermaidEncoder` that image views use: `pako:` plus URL-safe Base64 of deflated `{ "code":"…", "mermaid":{"theme":"default"}}`, or plain URL-safe Base64 with compression off ([`MermaidEncoder.java` L14–L31](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-import/src/main/java/com/structurizr/importer/diagrams/mermaid/MermaidEncoder.java#L14-L31)).
- Properties, read from the view set's properties only ([L90–L119](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/Mermaid.java#L90-L119)):
  - `mermaid.url`: required; the parse fails without it.
  - `mermaid.format`: `svg` (default) or `png`; anything else fails the parse.
  - `mermaid.compress`: `true` by default; `false` gives plain Base64.
  - `mermaid.inline`: ignored. Only image views honor it ([`MermaidImporter.java` L72–L83](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-import/src/main/java/com/structurizr/importer/diagrams/mermaid/MermaidImporter.java#L72-L83)), so a documentation block always becomes a link to the Mermaid server.
- With `mermaid.format` set to `png`, the plugin writes `<mermaid.url>/png/<encoded>`, while image views write `<mermaid.url>/img/<encoded>?type=png` ([`MermaidImporter.java` L66–L70](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-import/src/main/java/com/structurizr/importer/diagrams/mermaid/MermaidImporter.java#L66-L70)). On 2026-11-13, `https://mermaid.ink/svg/…` and `/img/…` answered 200 and `/png/…` answered 404, so the `png` form looks broken against mermaid.ink.

The PlantUML plugin works the same way with `plantuml.url` (required) and `plantuml.format` (`svg` or `png`), matching ` ```plantuml ` and `[plantuml]` blocks and encoding with `PlantUMLEncoder` ([`PlantUML.java` L20–L113](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/PlantUML.java#L20-L113)). It also ignores `plantuml.inline`.

**No Kroki plugin exists for documentation.** `kroki.url`, `kroki.format` and `kroki.inline` belong to image views only ([`KrokiImporter.java` L17–L19](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-import/src/main/java/com/structurizr/importer/diagrams/kroki/KrokiImporter.java#L17-L19)), and the documentation plugin folder holds only `Mermaid.java` and `PlantUML.java`. A ` ```kroki ` block always reaches the page as code.

**So the workspace JSON stores one of two things.** Without the plugin, a section's `content` holds the fenced source exactly as written. With the plugin, it holds an image link whose last path segment encodes the source; the fence and the plain source are gone from the JSON. The encoded form is the same one Renderizr already decodes for image views ([ADR 24](../architecture/decisions/0024-add-support-for-mermaid-diagrams.md)), so the source stays recoverable, under the same caveat that the compressed form escapes only newlines and quotes.

## 3. Embedding a view with `embed:`

Structurizr's image rule checks whether a Markdown image's `src` starts with `embed:`; if so, it takes the text after the first colon, URI-decodes it and embeds the view with that key ([L16–L29](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L16-L29)). The forms ([docs: Diagrams](https://docs.structurizr.com/server/documentation/diagrams), [source L12–L48](https://github.com/structurizr/structurizr.github.io/blob/530a96451b93f8fb96337b58aaaa1ec8c0ad4589/commands/03-server/23-documentation/02-diagrams.md?plain=1#L12-L48)):

- Markdown `![](embed:SystemContext)` and AsciiDoc `image::embed:SystemContext[]`. The AsciiDoc form must start the line; Structurizr ignores its attribute list ([L215–L218](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L215-L218)).
- Parameters in braces after the key: `embed:Key{type=graph}`, `embed:Key{perspective=Security}`, comma separated. Structurizr reads them only when no view has the whole string as its key. `type` takes `graph` or, undocumented, `tree`, both drawn 90 percent of the viewport high ([L71–L103](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L71-L103)).
- A published PNG URL of the same workspace, `…/workspace/<id>/images/<key>.png`, `…/share/<id>/images/<key>.png` or `…/share/<id>/<token>/images/<key>.png`, which Structurizr swaps for the live view ([L124–L142](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L124-L142)).

The result is an `<iframe class="structurizrEmbed">` on Structurizr's `/embed` page with the view key, perspective and type in the query ([L105–L118](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L105-L118)); the page passes its light or dark mode into each iframe when the reader switches ([`documentation.jsp` L383–L390](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/documentation.jsp#L383-L390)). An unknown key gives a red alert: "Unable to embed view '…' - there is no view with this key in the workspace." ([L120](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L120)). Other images resolve against `documentation.images` (the copies the importer embeds) or the `{workspace}/images/` prefix, and otherwise load as plain URLs ([L144–L193](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L144-L193)).

### Renderizr today

Renderizr handles no `embed:` form. Nothing under `src/` matches `embed:` outside comments, and three steps leave the link as it is:

1. markdown-it turns `![](embed:SystemContext)` into `<img src="embed:SystemContext" alt="">`; its link validator lets the `embed:` scheme through ([`markdown-renderer.ts` L91–L133](https://github.com/FormulaMonks/renderizr/blob/cf0c03d09abfa39b6545d9ae2225a2c6156614e2/src/components/markdown-renderer.ts#L91-L133)).
2. The image resolver skips any `src` with a scheme, so `embed:` stays ([`doc-images.ts` L7, L45](https://github.com/FormulaMonks/renderizr/blob/cf0c03d09abfa39b6545d9ae2225a2c6156614e2/src/components/doc-images.ts#L45)).
3. The AsciiDoc pass turns `image::embed:SystemContext[System Context, 600]` into `![System Context](embed:SystemContext)` ([`asciidoc.ts` L119–L124](https://github.com/FormulaMonks/renderizr/blob/cf0c03d09abfa39b6545d9ae2225a2c6156614e2/src/components/asciidoc.ts#L119-L124), [`asciidoc.test.js` L171–L174](https://github.com/FormulaMonks/renderizr/blob/cf0c03d09abfa39b6545d9ae2225a2c6156614e2/test/asciidoc.test.js#L171-L174)).

The browser then fails to load the `embed:` URL. Checked in Chromium on 2026-11-13: an image with empty alt text, which is what every Markdown `![](embed:Key)` produces, takes up no space at all, so the reader sees nothing where the view belongs, only the gap of an empty paragraph. An image with alt text (the AsciiDoc form with a caption, or `![Context](embed:Key)`) shows the broken-image icon followed by the alt text. Parameters fare the same: `embed:Key{type=graph}` becomes `src="embed:Key%7Btype=graph%7D"`. The versioned fixture [`test/__fixtures__/element-documentation.json`](https://github.com/FormulaMonks/renderizr/blob/cf0c03d09abfa39b6545d9ae2225a2c6156614e2/test/__fixtures__/element-documentation.json#L538) carries `![](embed:SystemContext)`, `![](embed:Containers)`, `![](embed:Components)` and `image::embed:LiveDeployment[]`, so `pnpm dev -- test/__fixtures__/element-documentation.json` shows the gaps.

## 4. Mathematical expressions

Structurizr renders math with [KaTeX](https://katex.org) in Markdown, with two syntaxes of its own ([L31–L64](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L31-L64)):

- **Inline**: an inline code span whose content starts and ends with `$`, written `` `$E = mc^2$` ``. Structurizr strips the dollars and calls `katex.renderToString`; a parse error shows as `<code>` with the error text.
- **Display**: a fence with the info string `katex`. Structurizr splits the body on two or more line breaks and renders each part as its own display formula.

Neither matches GitHub's math syntax (`$…$`, `$$…$$`, ``$`…`$`` and ` ```math `): a ` ```math ` fence stays code, and bare `$…$` stays text. No setting turns math on or off; KaTeX loads on every documentation and decisions page ([`documentation.jsp` L9, L12](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/documentation.jsp#L9-L12)). The `ui` repo has the same two syntaxes with KaTeX 0.16.4 ([`ui` `structurizr-content.js` L29–L62](https://github.com/structurizr/ui/blob/3b2582c106f1a836e78696b7226fc5869fe9bad1/src/js/structurizr-content.js#L29-L62)). The docs site never mentions math; this behavior shows only in source. The fence check also contains a bug: the error branch writes the literal text `${err}` in single quotes ([L56](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L56)).

AsciiDoc gets no math. Structurizr sets no `stem` attribute and loads no MathJax, so even a document that sets `:stem:` shows its `stem:[…]` content as delimited text (inferred from the source; not tried in a browser).

## 5. Collapsed sections, color-scheme images and syntax highlighting

### Raw HTML and `<details>`

markdown-it passes raw HTML through whenever safe mode is off ([L10–L12](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L10-L12)), and the application hardcodes `isSafeMode()` to `false` ([`Configuration.java` L187–L189](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/configuration/Configuration.java#L187-L189)), as Lite ([Lite `Configuration.java` L132–L134](https://github.com/structurizr/lite/blob/cdcbb1ba784fad75d3c05fa1a3364ab17b221e51/src/main/java/com/structurizr/lite/Configuration.java#L132-L134)) and on-premises ([on-premises `Configuration.java` L210–L212](https://github.com/structurizr/onpremises/blob/d0de84817c96f0eb1867601414a19dd58ab5f066/structurizr-onpremises/src/main/java/com/structurizr/onpremises/configuration/Configuration.java#L210-L212)) did. No sanitizer runs. So `<details><summary>…</summary>…</details>` works as plain browser HTML, with Markdown inside it only when blank lines separate it from the tags (CommonMark's HTML block rule). Structurizr adds no styling or behavior of its own for it. Only the closed-source cloud service could turn safe mode on; nothing read here confirms whether it does. In safe mode, markdown-it escapes HTML and the AsciiDoc pass drops `++++` and `[pass]` passthroughs ([L205–L214](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L205-L214)).

### Images that follow the color scheme

Structurizr does nothing for them. No code reads a `#gh-dark-mode-only` or `#gh-light-mode-only` fragment, so both images of such a pair show. The page has its own light, dark and system modes ([`documentation.jsp` L335–L345](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/documentation.jsp#L335-L345), [`structurizr-ui.js` L750–L779](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-ui.js#L750-L779)) and passes them only to embedded views. A raw-HTML `<picture>` with `<source media="(prefers-color-scheme: dark)">` follows the operating system's scheme, so it disagrees with the page when the reader picks light or dark by hand (inferred from how `<picture>` works; not tried).

### Syntax highlighting

The application calls `hljs.highlightAll()` after it renders the content ([`documentation.jsp` L326–L327](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/documentation.jsp#L326-L327), [`decisions.jsp` L475](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/decisions.jsp#L475)). The bundle is highlight.js 11.11.1's common build of 36 grammars: bash, c, cpp, csharp, css, diff, go, graphql, ini, java, javascript, json, kotlin, less, lua, makefile, markdown, objectivec, perl, php, php-template, plaintext, python, python-repl, r, ruby, rust, scss, shell, sql, swift, typescript, vbnet, wasm, xml and yaml ([`highlight-11.11.1.min.js`](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/highlight-11.11.1.min.js)). The colors are GitHub's light and dark highlight themes, copied into `structurizr.css` and `structurizr-dark.css` ([`structurizr.css` L701–L712](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/css/structurizr.css#L701-L712), [`structurizr-dark.css` L240–L250](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/css/structurizr-dark.css#L240-L250)).

highlight.js treats three cases differently ([`highlight.js` L95–L108, L775](https://github.com/highlightjs/highlight.js/blob/11.11.1/src/highlight.js#L95-L108)):

- A fence with a bundled language (` ```java `) gets that grammar.
- A fence with an unknown language (` ```structurizr `, ` ```mermaid `) stays plain, with a console warning.
- A bare fence gets automatic detection across the 36 grammars. A sample Structurizr DSL workspace came out as PHP, with C++ second (checked with highlight.js 11.12's common build, which carries the same grammars).

AsciiDoc `[source,java]` blocks reach highlight.js too, since asciidoctor.js writes them as `<pre><code class="language-java">` (asciidoctor's standard HTML; not tried). The `ui` repo loads no highlight.js, so Lite, on-premises and the cloud service as of that code highlight nothing.
