## Answer

Structurizr renders documentation in the browser with markdown-it (plus footnotes) and asciidoctor.js, and turns on few GitHub extensions: tables, strikethrough and `<…>` autolinks come from markdown-it's defaults, while task lists, emoji, alerts and bare-URL links stay off. Its page draws no Mermaid, PlantUML or Kroki block; two opt-in DSL plugins (Mermaid and PlantUML, no Kroki) rewrite those fences at parse time into image links to the diagram server, so the workspace JSON holds either the fence as written or an encoded server URL. `![](embed:<key>)` and `image::embed:<key>[]` become live iframes in Structurizr, and Renderizr shows nothing in their place today. Math uses KaTeX with Structurizr's own syntax (`` `$…$` `` and ` ```katex `). Raw HTML passes unsanitized, images get no color-scheme handling, and highlight.js highlights 36 languages, none of them Structurizr DSL. The only DSL grammars are Structurizr's Ace mode and two small TextMate grammars in VS Code extensions; Linguist, highlight.js, Prism and Shiki have none.

I read `structurizr/structurizr` at [`ad34036`](https://github.com/structurizr/structurizr/tree/ad34036c5a1227535fc9adea9a0f97de5962189d) (2026-11-07), the consolidated application that replaces Lite and on-premises, plus the archived `ui`, `lite`, `onpremises` and `cli` repos and the docs site source at [`530a964`](https://github.com/structurizr/structurizr.github.io/tree/530a96451b93f8fb96337b58aaaa1ec8c0ad4589). The cloud service is closed source; its last public UI code is the archived [`ui` repo](https://github.com/structurizr/ui/tree/3b2582c106f1a836e78696b7226fc5869fe9bad1). Full notes with a citation behind every claim: `research/329-structurizr-documentation.md` on `chore/329/structurizr-documentation-rendering`.

## 1. Markdown and AsciiDoc libraries

- The application uses markdown-it 14.1.1 with markdown-it-footnote 4.0.0, asciidoctor.js 2.2.6, KaTeX 0.16.27 and highlight.js 11.11.1 ([`documentation.jsp` L6–L12](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/documentation.jsp#L6-L12)). The `ui` repo (Lite, on-premises, cloud) uses markdown-it 13.0.1 with no plugins, the same asciidoctor.js and KaTeX 0.16.4, and no highlight.js ([`ui` `documentation.jsp` L6–L10](https://github.com/structurizr/ui/blob/3b2582c106f1a836e78696b7226fc5869fe9bad1/src/jsp/documentation.jsp#L6-L10)). The docs name markdown-it and asciidoctor.js too ([Documentation](https://docs.structurizr.com/server/documentation)).
- Structurizr sets only `html: !safeMode` and the footnote plugin ([`structurizr-content.js` L10–L14](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L10-L14)); the rest is markdown-it's [default preset](https://github.com/markdown-it/markdown-it/blob/14.1.1/lib/presets/default.mjs#L5-L36). Tables and strikethrough: on. Autolinks: `<https://…>` only, since `linkify` is off. Footnotes: on in the application (since 2026.04.19), off in the `ui` repo. Task lists, emoji shortcodes, alerts and the typographer: off.
- AsciiDoc goes through `new Asciidoctor().convert()` with no options or attributes, after a line pass that handles `image::` lines ([L203–L232](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L203-L232)).

## 2. Mermaid, PlantUML and Kroki blocks

- The page draws none of them: "The Structurizr documentation renderer does not natively support diagramming formats such as PlantUML or Mermaid" ([Images](https://docs.structurizr.com/server/documentation/images)). Without a plugin, ` ```mermaid ` reaches the page as a plain code block.
- The DSL rewrites them only when the author adds `!plugin com.structurizr.dsl.plugin.documentation.Mermaid` (or `.PlantUML`) after every `!docs`, `!adrs` and `views` ([Mermaid plugin](https://docs.structurizr.com/dsl/plugins/mermaid), [PlantUML plugin](https://docs.structurizr.com/dsl/plugins/plantuml)). Both shipped in the application's 2026.02.01 release and live in `structurizr-application`; the archived `structurizr-cli` does not have them.
- The plugin runs at parse time and calls `setContent` on every section and decision of the workspace and of each element ([`Mermaid.java` L26–L48](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/Mermaid.java#L26-L48)). It matches `^```mermaid` up to `^```` (or `[mermaid]`with a`....` block) ([`AbstractDiagramsAsCodePlugin.java`L7–L16](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/AbstractDiagramsAsCodePlugin.java#L7-L16)) and replaces it with`![](<mermaid.url>/<format>/<encoded>)`or`image::…[]`, encoded with the same `MermaidEncoder` as image views ([`MermaidEncoder.java` L14–L31](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-import/src/main/java/com/structurizr/importer/diagrams/mermaid/MermaidEncoder.java#L14-L31)).
- Properties come from the view set only ([L90–L119](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/Mermaid.java#L90-L119)): `mermaid.url` (required), `mermaid.format` (`svg` default, or `png`) and `mermaid.compress` (`true` default). The plugin ignores `mermaid.inline`, so a documentation block never becomes a data URI. With `png` it writes `/png/…`, which mermaid.ink answers with a 404, while image views write `/img/…?type=png`. PlantUML takes `plantuml.url` and `plantuml.format` the same way ([`PlantUML.java` L93–L113](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/dsl/plugin/documentation/PlantUML.java#L93-L113)).
- Kroki has no documentation plugin: `kroki.url`, `kroki.format` and `kroki.inline` apply to image views only ([`KrokiImporter.java` L17–L19](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-import/src/main/java/com/structurizr/importer/diagrams/kroki/KrokiImporter.java#L17-L19)).
- So the workspace JSON holds the fence exactly as written ([`DefaultDocumentationImporter.java` L91–L93](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-import/src/main/java/com/structurizr/importer/documentation/DefaultDocumentationImporter.java#L91-L93)), or, with the plugin, an image link whose last segment encodes the source in the form ADR 24 already decodes.

## 3. Embedding a view

- Structurizr turns `![](embed:<key>)`, `image::embed:<key>[]` (at the start of a line) and a published PNG URL of the same workspace (`…/workspace/<id>/images/<key>.png` and the two `/share/` forms) into an iframe of its `/embed` page ([`structurizr-content.js` L16–L29, L66–L142](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L66-L142), [Diagrams](https://docs.structurizr.com/server/documentation/diagrams)). Braces after the key take `type=graph`, `type=tree` (undocumented) and `perspective=<name>`, read only when no view has the whole string as its key. An unknown key shows a red "Unable to embed view" alert.
- Renderizr handles none of these. markdown-it writes `<img src="embed:SystemContext" alt="">`, and the image resolver skips any `src` with a scheme ([`doc-images.ts` L45](https://github.com/FormulaMonks/renderizr/blob/cf0c03d09abfa39b6545d9ae2225a2c6156614e2/src/components/doc-images.ts#L45)); the AsciiDoc pass turns `image::embed:Key[Alt]` into `![Alt](embed:Key)` ([`asciidoc.ts` L119–L124](https://github.com/FormulaMonks/renderizr/blob/cf0c03d09abfa39b6545d9ae2225a2c6156614e2/src/components/asciidoc.ts#L119-L124)). In Chromium, the empty-alt image takes no space, so the reader sees an empty gap where the view belongs; with alt text, the reader sees a broken-image icon and the alt text. `test/__fixtures__/element-documentation.json` shows it with `pnpm dev -- test/__fixtures__/element-documentation.json`.

## 4. Math

- KaTeX, with two syntaxes of Structurizr's own ([L31–L64](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/structurizr-content.js#L31-L64)): an inline code span wrapped in dollars, `` `$E = mc^2$` ``, and a ` ```katex ` fence, where blank lines separate display formulas. KaTeX loads on every documentation and decisions page; nothing configures it. The docs never mention it.
- GitHub's `$…$`, `$$…$$` and ` ```math ` do not render. AsciiDoc gets no math: Structurizr sets no `stem` attribute and loads no MathJax.

## 5. Collapsed sections, color-scheme images and highlighting

- Raw HTML passes unsanitized, since the application, Lite and on-premises all hardcode safe mode off ([`Configuration.java` L187–L189](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/java/com/structurizr/configuration/Configuration.java#L187-L189)). `<details>` works as plain browser HTML with no styling of Structurizr's own. Only the closed cloud service could turn safe mode on.
- Images get no color-scheme handling: nothing reads `#gh-dark-mode-only`, and the page's light, dark and system modes reach only embedded views ([`documentation.jsp` L383–L390](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/documentation.jsp#L383-L390)).
- The application calls `hljs.highlightAll()` ([`documentation.jsp` L327](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/webapp/WEB-INF/jsp/documentation.jsp#L327)) with highlight.js's 36-language common build and GitHub's light and dark colors. A fence with an unknown language stays plain; a bare fence gets auto-detected, and a sample DSL workspace came out as PHP. The `ui` repo highlights nothing.

## 6. Structurizr DSL

- Structurizr does not highlight DSL in documentation; no bundled grammar covers it.
- Its docs write DSL in bare fences (399 under `dsl/`, none named `structurizr`, `dsl` or `c4`). Tools name the language `structurizr` (Structurizr's Ace mode, `ciarant.vscode-structurizr`) or `c4` (`systemticks.c4-dsl-extension`).
- Grammars that exist:
  - Structurizr's DSL editor and playground: an Ace mode, [`mode-structurizr.js`](https://github.com/structurizr/structurizr/blob/ad34036c5a1227535fc9adea9a0f97de5962189d/structurizr-application/src/main/resources/static/static/js/ace/mode-structurizr.js), 350 lines of line-based regex rules, Apache 2.0.
  - [`ciarant/vscode-structurizr`](https://github.com/ciarant/vscode-structurizr) (about 50,000 installs, last release 2022): a TextMate grammar, [`structurizr.tmLanguage.json`](https://github.com/ciarant/vscode-structurizr/blob/00e213254f8f0b1d229fe470a24a771a7fc111b9/syntaxes/structurizr.tmLanguage.json), scope `source.structurizr`, about 2.9 KB, MIT.
  - [`systemticks/c4-grammar`](https://gitlab.com/systemticks/c4-grammar) on GitLab, the C4 DSL Extension (about 64,000 installs, last release January 2025): a TextMate grammar, `c4.tmLanguage.json`, scope `source.c4`, about 3 KB, plus a Java language server, Apache 2.0.
  - IntelliJ, Emacs and Zed plugins exist; I did not read them.
- highlight.js, Prism and Shiki list no Structurizr grammar. [GitHub Linguist](https://github.com/github-linguist/linguist/blob/d456527fe93355baa28c3c29d542c97282b61bc7/lib/linguist/languages.yml#L166-L173) has no Structurizr entry and maps `.dsl` to ASL, so a ` ```structurizr ` fence renders plain on GitHub.

## What this means for Renderizr

- Footnotes are the one GitHub extension Structurizr's application turns on that Renderizr lacks. Renderizr already matches or exceeds Structurizr on tables, strikethrough, raw HTML and alerts, and neither renders task lists, emoji shortcodes or bare-URL links.
- `embed:` is the one Structurizr documentation feature that loses content in Renderizr today: every `![](embed:<key>)` leaves an empty gap. Renderizr can draw the view itself, with the `{type=…}` and `{perspective=…}` parameters and the published PNG URL as forms to consider.
- A workspace reaches Renderizr with Mermaid either as a raw ` ```mermaid ` fence (no plugin, or a JSON workspace) or as a `<mermaid.url>/svg/<encoded>` image link (plugin on). ADR 24's decoder already reads the second form, so both could draw as Mermaid diagrams. The plugin form needs the consolidated `structurizr` application, while a DSL session runs `structurizr-cli` unless `STRUCTURIZR_CLI` says otherwise (ADR 16), and that CLI lacks the plugin classes. Without that, the plugin form needs the network to show anything, and the `png` form is broken against mermaid.ink. PlantUML and Kroki have no in-page renderer in Structurizr either.
- Structurizr's math syntax (`` `$…$` `` and ` ```katex `) differs from GitHub's (`$…$`, `$$…$$`, ` ```math `). Supporting one does not render workspaces written for the other.
- No grammar for Structurizr DSL exists in highlight.js, Prism, Shiki or Linguist. The available starting points are two small TextMate grammars (MIT and Apache 2.0, a few KB each) and Structurizr's Ace mode (Apache 2.0). Structurizr itself gives authors no fence name to follow: its docs use bare fences, and tools use `structurizr` or `c4`.
- Neither tool handles images that follow the color scheme; Renderizr has no Structurizr behavior to match there.
